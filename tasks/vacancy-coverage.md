# 空き状況の対応範囲と、探し尽くしたかの記録

最終確認: 2026-09-05（476自治体）

## いまの数

- **476自治体・29,306施設**（全国1,747自治体のうち27%）
- 基準日の内訳: 2026年10月 6／9月 201／8月 258／7月 7／6月 3／5月 1

母数の1,747は総務省「全国地方公共団体コード」（R6.1.1現在）の市区町村＋特別区。

## あとどれくらい見つかるか（2026-09-05に測った）

**探索の発見率を測った。** 取り込み済みの自治体から60件を無作為に選び、
同じ道具でその自治体を「見つけられるか」を試す。見つけられなければ、
まだ取り込めていない自治体も同じように見落としているはずである。

| 道具の版 | 発見率 | 直したこと |
|---|---|---|
| vdeep6 | 51/60（85%） | — |
| vdeep7 | 57/60（95%） | サイトマップの起点を150→500件、資料の名前の手掛かりを拡張 |

発見率95%で476自治体を見つけているので、**公表している自治体は全部で約500件**、
つまり**未発見はおよそ25件**と見積もれる。

この見積もりには偏りがある。標本にしたのは「見つけられた」自治体なので、
発見しやすい側に寄っている。実際の残りは25件より多い可能性がある。

発見率95%の版で未取り込み1,134件を全件回した結果、
**新たに取り込めたのは岩沼市の1件だけ**だった。候補として挙がったものは
すべて、すでに取り込み済みか、下の「取り込まない」表に当てはまるものだった。

母数1,747のうち約1,250自治体は、そもそも施設別・年齢別の空き状況を公表していない。
町村が中心で、電話での問い合わせのみという運用が一般的である。

### さらに大きな穴：ホスト名の www の有無（2026-09-05）

探索の道具は `https://<ホスト>/` を叩くだけで、**www を補っていなかった**。
リストのホストが `city.saku.nagano.jp` のように www 抜きで書かれていて、
その書き方では繋がらない自治体は、トップページすら開けないまま
「公表なし」と数えられていた。

全1,283件について www の有無を入れ替えて到達を確かめたところ
（`scratchpad/vwww.py`）、**88自治体がこれに当たった**。
探索の道具側も www を補うように直した（`scratchpad/vdeep5.py` の `resolve_host`）。

www を補って93件を回し直した結果、**上里町（7施設）と高浜市（11施設）**が新たに見つかった。

### ホスト名の書き方（lg.jp とドメイン）（2026-09-05）

繋がらない94件のホスト名を、Wikidataが持つ公式サイトのURLと突き合わせ、
また `www.city.<名>.<県>.jp` を `www.city.<名>.lg.jp` に読み替えて確かめたところ、
**66件が正しいホストに直せた**。この66件も一度も探索できていなかった。

直して回した結果、**茅野市（20施設）・下妻市（12施設）・阪南市（7施設）・
新城市（14施設）・伊奈町（12施設）**が新たに見つかった。

| 直し方 | 件数 | 例 |
|---|---|---|
| Wikidataの公式サイト | 23 | 茅野市 www.city.chino.nagano.jp → www.city.chino.lg.jp |
| `<県>.jp` → `lg.jp` の読み替え | 43 | 新城市 www.city.shinshiro.aichi.jp → www.city.shinshiro.lg.jp |

### この環境から開けない28自治体

ホスト名を直しても繋がらない自治体が28件残っている。一覧は
`tasks/vacancy-unreachable.tsv`。

そのうち4件（厚岸町・上士幌町・姫島村・南相木村）は
`www.akkeshi-town.jp` のような独自ドメインで、あとから見つかった。

**ドメインを当て推量するときは、必ずそのページに自治体名が出るか照合すること。**
`www.ina.jp`（伊那市のつもり）はドメイン販売の案内、
`www.kashima.jp`（鹿島市のつもり）は福島県いわき市の病院、
`www.mugi.jp`（牟岐町のつもり）は同人サークルのサイトだった。
12件当てて、本物は4件だけだった。

- DNSは引けるが、443にも80にも、IPv4でもIPv6でもTCP接続がタイムアウトする
- 時間をあけて2度確かめても変わらなかった（1件だけ繋がるようになった）
- curl でも Python でも同じなので、道具ではなく経路の問題
- 高山市・甲賀市・茅野市・七尾市・下妻市・豊岡市・伊那市・玉野市など、
  規模の大きい市が多く含まれる

**別の回線から確かめ直す必要がある。**

**つまり「1,747件すべて確認済み」とは言えない。**
確認できていないのは26件（残り24件＋大山町・豊丘村）。

確認に使った探し方は4通り。どれか1つでは取りこぼすので重ねている。

| 探し方 | 何を手がかりにするか | 見つかった数 |
|---|---|---|
| リンクの文字（狭い語彙） | 「空き状況」「受入可能」 | 大半 |
| リンクの文字（広い語彙） | 「入所可能」「欠員」「定員と現員」「あき情報」など | 富谷市・吉田町ほか |
| **ページの中身** | 0〜5歳の列を持つ表があるか | 登別市・三芳町・三郷町・大台町 |
| 別ドメインの子育てサイト | トップから外に出る「子育て」リンクの先 | 0件（狛江市・竜王町は既に取り込み済み） |

道具は `scratchpad` に置いてある（vwide.py／vcontent.py／vkosodate.py／vspot.py／vresolve.py）。

## 取り込みが止まっていないかの見張り（2026-09-04に足した）

**基準日だけを見ていると、更新の取りこぼしに気づけない。** 実際に3種類の穴があった。

| 穴 | どう気づいたか | 直し方 |
|---|---|---|
| 自動更新に22自治体が入っていなかった | データはあるのにワークフローに無い、を突き合わせた | 個別ステップに無いものをまとめて回すステップを足した |
| 基準日の年・日付がずれていた（呉市2025年、熊野町が締切日） | 基準日と取得日の開きを見た | verify に日付の点検を足した（200日以上前／40日以上あとで中断） |
| 基準日を変えずに資料が差し替わっていた | 保存しているURLが404になっていた | 判定に取り込み元URLを足した。`npm run vacancy:check:sources` で404を探す |

3つとも**既存の verify では見つからなかった**。verify の検算値は基準日が変わると
照合をスキップするため。取り込み元と突き合わせる点検を別に持つこと。

## 同名の自治体の取り違えに注意

2026-09-04、**八千代町（茨城）として八千代市（千葉）のデータを公開していた**ことが分かり、
入れ替えた。取り込み済み445件すべてについて「出典ページに自治体名が出るか」を機械照合し、
これ1件だけと確かめている（`scratchpad/vname.py`）。

那賀町→那珂市、香南市→江南市、さくら市→佐倉市、柴田町→新発田市、大山町→大仙市、
豊丘村→豊岡市、三木町（香川）→三木市（兵庫）。**ホスト名やスラッグだけで判断しない。**

探索リストのホスト名は `scratchpad/vhost.py` で全件照合できる。
