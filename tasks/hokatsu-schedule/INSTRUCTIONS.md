# 保活スケジュールレコードの収集手順（サブエージェント向け）

自治体ごとの「保活スケジュール」記事は、`src/lib/articles/hokatsu-schedule/records/<slug>.json` の**レコード**から組み立てる。
あなたの仕事は、割り当てられた自治体（1つだけ）について公式ページを読み、レコードを作ること。文章は書かない。
事実だけを、根拠の原文（quote）つきで書く。

対象は **令和9年4月（2027年4月）入園** の申込スケジュール。いま（2026年9月）多くの自治体が案内を出し始めている。

## 守ること（最初に読む）

1. **サブエージェントを使わない。** 自分で curl で取り、自分で読み、自分で書く。
2. **推測で埋めない。** 公式ページに書いていないフィールドは JSON に入れない。書いたことはすべて `evidence` の quote で裏づける。**値は quote から読み取れる範囲を出ない。**
3. **年度を取り違えない。** 「令和9年4月入園」「令和9年度」「2027年4月」の案内を探す。ページの更新日と見出しの年度を必ず見る。
   令和9年4月入園の案内がまだ無ければ、**令和8年4月入園（2026年4月）の案内**を `fiscalYear: "R8"` で書く（その場合も日付は令和7年の実日付を書く。令和9年の日付に読み替えない）。
4. **日付は年月日の入った文から引く。**「10〜11月頃」のような目安は書かない。quote には「令和8年10月1日」のように年月日が入る文を使う。
5. **WebFetch の要約に頼らない。** `curl -sL -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/128.0 Safari/537.36" -o <保存先> <URL>` で HTML/PDF を保存し、
   タグを外してテキストに書き出し、grep で行番号を見てから必要な範囲だけ Read の offset/limit で読む（全文 Read はしない）。
   PDF は pdfplumber（駄目なら pypdf）でテキスト化してから同じように読む。
   WebSearch は使ってよいが、**結果の URL は必ず curl で 200 を確かめてから**使う。
6. **同名自治体に注意。** 主ページ（page）の本文に、その自治体の名前が出ていることを確認する。
7. 自治体の公式ドメインだけを出典にする。まとめサイト・保育園のサイトは不可。
8. **時間やトークンの制約は無い。**「効率化のため簡略化」「指示待ち」「途中報告」「仮レコード」は禁止。
   **レコードを書いて照合を○にしてから**、1回だけ報告する。**レコードを書かずに完了と報告することは禁止。**

## 探し方

1. WebSearch で `<自治体名> 令和9年4月 保育所 入所申込`、`<自治体名> 令和9年度 保育園 申込 案内`、`<自治体名> 保育所 利用申込 スケジュール` を検索し、公式ドメインの結果を curl で取る。
2. 4月入園の申込案内ページ（受付期間・結果通知・必要書類が書いてあるページ）を `page` にする。案内が PDF（「入園のご案内」冊子）にしか無ければ、その PDF を読んで、`page` にはリンク元のHTMLページ、evidence の url には PDF を書く。
3. 一次申込の受付期間が取れないレコードは作らない（R9 が無ければ R8 の案内から取る）。

## JSON の形

`records/tsu.json` を手本にする（形の手本。**文や値は流用しない**）。キーの意味:

| キー | 書くこと | 必須 |
|---|---|---|
| citySlug | ファイル名と同じ | 必須 |
| checkedAt | 今日の日付 `2026-09-18` | 必須 |
| page | 4月入園の申込案内ページ `{label, url}`。label は「◯◯市「ページ名」」 | 必須 |
| fiscalYear | `"R9"`（令和9年4月入園の日程）か `"R8"`（令和8年4月入園の実績しか無いとき） | 必須 |
| guideRelease | 案内・申込書の配布開始（日付と場所） | あれば |
| firstApply | 一次申込の受付期間（年月日。窓口・郵送・電子で締切が違えば併記） | 必須（無ければ R8 で） |
| applyMethods | 申込方法（窓口・郵送・電子申請の別、受付場所） | あれば |
| firstResult | 一次結果の通知時期（年月と方法） | あれば |
| secondApply | 二次申込の受付期間 | あれば |
| secondResult | 二次結果の通知時期 | あれば |
| midYearDeadline | 年度途中入園の締切（毎月○日など） | あれば |
| documents | 必要書類。1つ1要素。就労証明書の証明日・有効期限の条件があれば要素に含める | あれば |
| interview | 面接・健康診断・見学の要否と時期 | あれば |
| ikukyu | 育休延長希望の扱い（入園保留通知、希望園の書き方など） | あれば |
| notes | この自治体の案内に書かれている固有の注意。1つ1要素、2〜6個 | 必須（空配列可） |
| evidence | フィールド名 → `{url, quote}`。配列は `documents.0` `notes.1` のように要素ごと。**fiscalYear にも evidence（「令和9年4月入園」などの文言）** | 必須 |
| sources | 参照した公式ページ `{label, url}`。page を含める | 必須 |

### evidence の quote のルール

- **その値の根拠になっている本文の一続きの文**をそのまま写す（10〜80文字）。要約・言い換え・つなぎ合わせは不可
- **ページ名・見出し・ファイル名を quote にしない**（検査で弾かれる）
- 空白・全角半角・改行の違いは照合で無視される
- 値のあるフィールドすべてに evidence を付ける
- 日付の quote は、年月日が入っている文にする

## これまでに出た間違い（就労証明書・一時保育のときに出たもの。同じことをしない）

- **報告だけして中身が空**（evidence が空のスタブ、作り物の URL）。レコードは照合○になるまで直し、それから報告する
- **手本の quote や値を流用した**。手本は形だけ
- **quote に無い内容を値に書いた**（施設数、減免額、期日）。値は quote から読み取れる範囲を出ない
- **古い年度のページを引いた**（令和6年度の試行事業、記者発表、予算資料）。ページの更新日と年度を見る
- **「ページが無い」と報告した**が、`site:` 検索で1分で見つかった。無いと言う前に3通りの語で検索する
- **短い UA を 403 で弾くサイト**がある。上の Chrome UA を使う

## 終わったら

1. `LC_ALL=C.UTF-8 python scripts/verify-fact-records.py hokatsu <slug>` が○になるまで直す
2. 「slug／fiscalYear／一次申込の受付期間／一次結果／取れなかったフィールド／迷った点」を1行で報告する

## コンテキストを使い切らないために（重要）

- HTML はタグを外してテキストファイルに書き出し、まず `grep -n "令和9\|令和8\|申込\|受付\|締切\|結果\|通知\|書類\|証明書\|面接\|健康診断\|育児休業\|育休\|途中"` で行番号を見て、**必要な行の前後だけ Read の offset/limit で読む**
- PDF も同様に、抽出テキストをファイルに書いて grep してから読む
