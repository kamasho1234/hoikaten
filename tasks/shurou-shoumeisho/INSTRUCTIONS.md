# 就労証明書レコードの収集手順（サブエージェント向け）

自治体ごとの就労証明書の記事は、`src/lib/articles/shurou-shoumeisho/records/<slug>.json` の
**レコード**から組み立てる。あなたの仕事は、割り当てられた自治体について、公式ページを読んで
このレコードを1件ずつ作ること。文章は書かない。事実だけを、根拠の原文つきで書く。

## 守ること（最初に読む）

1. **サブエージェントを使わない。** 自分で curl で取り、自分で読み、自分で書く。
2. **1自治体ずつ最後まで。** 取る → 読む → JSON を書く → `python scripts/verify-shurou-records.py <slug>` で○にする → 次へ。
3. **推測で埋めない。** 公式ページに書いていないフィールドは JSON に入れない（記事には「記載なし」と出る）。
   「たぶんこうだろう」は一切書かない。書いたことはすべて `evidence` の quote で裏づける。
4. **WebFetch の要約に頼らない。** `curl -sL -A "Mozilla/5.0" -o <保存先> <URL>` で HTML/PDF を保存し、
   保存したファイルを自分で読む（HTML はタグを外す。PDF は `python -c "from pypdf import PdfReader; ..."`）。
   検索は WebSearch を使ってよいが、**検索結果の URL は必ず curl で 200 を確かめてから**使う。
5. **同名自治体に注意。** 様式ページの本文に、その自治体の名前（例「府中町」「大野市」）が出ていることを確認する。
   `targets.tsv` の都道府県と一致しているか見る。
6. 対象は**認可保育所等の利用申込に使う就労証明書**。学童や幼稚園の預かり保育だけの様式ではない。
7. 自治体の公式ドメイン（`city.*.lg.jp`、`town.*.jp`、`*.tokyo.jp` など）だけを出典にする。まとめサイト・保育園のサイトは不可。

## 保存先

- 取ったファイル: `<scratchpad>/shurou/<slug>/`（scratchpad のパスは依頼文に書いてある）
- レコード: `src/lib/articles/shurou-shoumeisho/records/<slug>.json`

## 探し方

1. `targets.tsv` の「既存記事の様式URL」があればそこから。無ければ WebSearch で
   `<自治体名> 就労証明書 保育` を検索し、公式ドメインの結果を curl で取る。
2. 様式の配布ページ（PDF/Excel のリンクがあるページ）を `formPage` にする。
   申込案内のページ（締切・提出先・有効期限）と、電子申請のページも読む。
3. 様式の PDF を必ず開いて、**国の標準様式かどうか**を自分で判定する。判定の基準:
   - 標準様式の特徴: 「No.」欄に 1〜19 の番号、「19 保護者記載欄」、「13 保育士等としての勤務実態の有無」、
     「15 入所内定時育休短縮可否」「16 育休延長可否」「17 単身赴任期間」、
     「※本証明書の内容について、就労先事業者等に無断で作成し又は改変を行ったときには、刑法上の罪に問われる場合があります。」
   - 上の項目がそろっていて自治体独自の欄が無い → `"standard"`
   - 上の項目がそろっているが、自治体の欄（雇用保険、通勤時間、様式番号、自治体独自の注意書きページなど）が足されている → `"standard-plus"`
   - 項目の並びや番号が違う、独自の項目がある（就労状況申告、通勤経路、月収など）→ `"original"`
   - `evidence.formType` には、判定の根拠になる**様式 PDF の中の文**（例「19 保護者記載欄」や独自欄の名前）を引く

## JSON の形

`records/setagaya.json` を手本にする。キーの意味:

| キー | 書くこと | 必須 |
|---|---|---|
| citySlug | ファイル名と同じ | 必須 |
| checkedAt | 今日の日付 `YYYY-MM-DD` | 必須 |
| formType | `standard` / `standard-plus` / `original` | 必須 |
| formPage | 様式の配布ページ `{label, url}`。label は「◯◯市「ページ名」」の形 | 必須 |
| formFiles | 様式 PDF・Excel・記入例・別紙の `{label, url}` の配列。URL は絶対URL | あれば |
| validity | 証明日からの有効期限。公式の文言をほぼそのまま（例「証明日から3か月以内のもの」） | あれば |
| deadline | 直近の申込締切（令和9年4月入園の一次・二次、通常月の締切） | あれば |
| submitTo | 提出先（課の名前、郵送可否） | あれば |
| online | 電子申請の可否と方法（マイナポータル・LoGoフォームなど）。就労証明書を電子で添付できるかも | あれば |
| siblings | きょうだいで1枚を兼用できるか（コピー可など） | あれば |
| seal | `required` / `not-required` / `unknown`。公式に書いていなければ `unknown` | 必須 |
| sealNote | 押印について公式の文言（seal が unknown でないとき） | あれば |
| selfEmployedDocs | 自営業・フリーランスが添える書類。1書類1要素 | あれば |
| differences | `original` / `standard-plus` のとき、国の標準様式との違い。欄の名前で具体的に | 独自様式なら必須 |
| notes | この自治体の記入例・注意書きに書かれている固有の注意。1つ1要素、3〜8個 | 必須（空配列不可） |
| evidence | フィールド名 → `{url, quote}`。配列は `notes.0` `notes.1` のように要素ごと | 必須 |
| sources | 参照した公式ページ `{label, url}`。formPage を含める | 必須 |

### evidence の quote のルール

- **ページ本文（PDF なら抽出テキスト）にそのまま出てくる一続きの文**を写す。要約・言い換え・つなぎ合わせは不可
- 10〜80文字くらい。短すぎると別の場所にも一致してしまう
- 空白・全角半角・改行の違いは照合で無視されるので、そこは気にしなくてよい
- 値のあるフィールドすべてに evidence を付ける（validity/deadline/submitTo/online/siblings/seal/selfEmployedDocs/differences/notes/formType）

### notes に書くこと・書かないこと

- 書く: 公式の記入例・注意書きにある固有の注意（不規則勤務は別紙、内定者は採用通知書、育休中の扱い、
  訂正は二重線、有効期限の数え方、様式が年度で変わった、など）
- 書かない: 国の記載要領と同じ一般論（休憩を含む、西暦で書く、など）。他の自治体の話。推測。

## 終わったら

1. `python scripts/verify-shurou-records.py <slug1> <slug2> ...` が全件○になるまで直す
2. 最後に、担当した自治体ごとに「slug／formType／取れなかったフィールド／迷った点」を1行ずつ報告する。
   ページが見つからない・様式が公開されていない自治体は、レコードを作らず、その理由を報告する

## これまでに出た間違い（同じことをしない）

- **手本（setagaya.json / osaka.json）の quote や値を流用した**（千葉市のレコードに世田谷区の文が入っていた）。手本は形の参考にするだけ。文は必ず担当自治体のページから写す
- **validity に有効期限でないものを入れた**（「直近3か月の就労実績に基づく」「父母それぞれで作成が必要」「年1回の確認時に提出」）。validity は「証明日から○か月以内」「○年○月○日以降の証明日のもの」のように、**証明日がいつなら受け付けるか**だけ。無ければ省く
- **notes に国の記載要領と同じ一般論を入れた**（コアタイムの定めがない場合…、シフト表の追加提出…、育休で実績が無い場合…）。これは全国共通なので書かない。自治体固有の注意だけ
- **quote に無い内容を値に書いた**（「新規採用等で就労実績がない場合は事業者判断で記載する」。原文は「今後の就労見込みを記載」）。値は quote から読み取れる範囲を出ない
- **現況届（在園児の年1回の確認）のページを様式ページにした**（北九州市）。対象は新規の利用申込のページ。同じ様式でも、締切・提出先は新規申込のものを書く
- **submitTo / online / deadline に別の内容を入れた**（online に希望園変更の電話受付期間、submitTo に郵送受付期間）。フィールドの意味どおりに。合わないものは省く
- **様式ファイルを開かずに formType を決めた**。様式名や「標準様式に変更しました」の文言は補助にはなるが、必ず PDF/Excel を開いて 19 項目を確認する
- **作業ディレクトリ直下に JSON を書いた**。保存先は必ず `src/lib/articles/shurou-shoumeisho/records/<slug>.json`
- 「トークンや時間の制約があるので簡略化する／指示を待つ」と言って止まった。制約は無い。止まらず最後まで進める
