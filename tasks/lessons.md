`git push origin master` したが、このリポジトリの本番ブランチは **main**。
`master` は初回コミットだけの古い stub で、Vercel は見ていない。

**push の前に `git branch --show-current` を見る。本番反映の確認は必ず正しいURLで行う**
（このときは `/articles/uto-guide` という存在しないURLで待っていて、404を「未反映」と読んでいた。
自治体記事は `/<slug>/articles/<記事slug>`）。

# 教訓

## push 先のブランチを毎回確認する（2026-08-21）

**何があったか**: `git push origin master` を実行して成功していたが、
このリポジトリの本番ブランチは `main` だった。ローカルに残っていた古い
`master`（initial commit のまま）へ push していたので、
「push 成功」なのに Vercel は何も拾わず、本番に20分以上反映されなかった。

**なぜ間違えたか**: セッション開始時のコンテキストに出る
「Current branch: master」は、ホームディレクトリ（`C:\Users\kamas`）の
別のリポジトリの状態だった。プロジェクト側のブランチとは関係がない。

**どうするか**: push の前に `git branch --show-current` で今いるブランチを
確認し、そのブランチ名で push する。push のあとは
`git log --oneline -1 origin/<branch>` で本当に届いたかを見る。
本番URLへの curl だけでは「デプロイが遅い」のか「そもそも届いていない」のかが
分からないので、まずリモートの ref を見ること。

## 記事ファイルは register-all.ts に import しないと出ない（2026-09-07）

`src/lib/articles/<slug>.ts` を作っただけでは記事は公開されない。
`register-all.ts` に `import "./<slug>";` を足して初めて `registerArticles()` が走る。

**足し忘れても型チェックもビルドも通る。** そのページだけが静かに404になる。
実際に7自治体・72本の記事が、この抜けで長い間公開されていなかった。

新しく記事ファイルを作ったら、必ず `npm run articles:verify` を通すこと
（`npm run build` の前に自動で走るようにしてある）。
記事を足したら、本番URLにcurlして200を確かめるところまでやる。

## 記事slugは半角英数とハイフンだけにする（2026-09-07）

見た目が同じでも別の文字が混ざるとページが出ない。
実際に `lotterу` の у がキリル文字（U+0443）になっていた記事があった。
日本語のslug（`途中入所-guide`）も同じく出ない。

`npm run articles:verify` で確認するようにしたが、
**記事を足したら本番URLにcurlして200を確かめる**のを省かないこと。
今回もそれで見つけた。

## 公開したあとにも、出典URLから照合し直す（2026-09-07）

記事を書くときの照合は「その場の資料」に対するもので、
**公開中の記事が今も正しいか**は別の話。

実際、以前に作られた保育料の記事47件が、自治体の公表していない
「世帯年収別の目安表」を載せていた。11自治体がまったく同じ表を共有し、
出典URLは1件も無かった。書いた時点では誰も気付かない形で残っていた。

`python scripts/verify-fee-articles.py` を定期的に走らせる。
記事に載せたURLから資料を取り直し、金額がその資料に出てくるかを見る。
「合わない」が1件でも出たら、その自治体の資料を目で確かめる。

## 原典が計算例を載せているときは、それを検証ケースにする（2026-09-08）

笛吹市の利用調整基準には計算例が載っていた。
「（父）家庭外労働100点 ＋（母）自営業（従業員）75点 ＝ 合計175点」。
これをそのまま `scripts/smoke-scoring.ts` のケースにすれば、
採点方式（sum/min）も選択肢の点数も、原典の答えと突き合わせて確かめられる。

自分で組み立てたケースは「自分の読み取りが正しい」という前提の上に乗っているが、
原典の計算例は自治体が出した答えなので、その前提ごと確かめられる。
新しい自治体を足すときは、まず原典に計算例が無いか探す。

## 固定した依存が消えることがある。CIの失敗は放置しない（2026-09-08）

`opencv-python-headless==4.13.0.88` が配布から取り下げられ（yanked）、
毎朝の空き状況更新が5日以上失敗し続けていた。
バージョン固定は再現性のために要るが、**消えたときに気付く仕組みが無かった**。

作業の切りのいいところで `gh run list` を見る。
失敗が続いていたら、その場で原因まで見る。

## 直し方が他を壊すなら、直さずに記録して戻す（2026-09-08）

西尾市の読み取りの誤り（空欄6マスが「クラスなし」）の原因は測れたが、
その直し方は荒川区と吹田市を壊した。
`npm run vacancy:verify` が検出したので変更を戻した。

**部分的に良くなるからといって、他を壊す変更を入れない。**

次に直すときの出発点になる。

## 同じ名前の自治体がいる。登録前に必ず確かめる（2026-09-09）

日本には同じ名前の市町村がある。slug をそのまま付けると別の自治体を上書きする。

これまでに当たったもの:
- 中野市（長野）と中野区（東京）… `nakano` は中野区。市は `nakano-nagano`
- 伊達市（北海道）と伊達市（福島）… 福島が `date-fukushima`。北海道は `date-hokkaido`
- 大仙市（秋田）… `daisen` は空いていた。「鳥取に大山町がある」は私の思い込みで実在しなかった

**手順**: 新しい自治体を足す前に
`grep -rl "<自治体名>" src/lib/data/*.ts` と
`ls src/lib/data/<slug>.ts src/lib/vacancy/<slug>.json` を見る。
空き状況データが先に slug を使っていることもあるので、そちらも確認する。
思い込みで「同名がある／ない」と決めない。
